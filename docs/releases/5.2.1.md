# Remnawave Admin 5.2.1

23 ноября 2026

Технический релиз: проект переехал в самостоятельный репозиторий `mslab-tech/remnawave-admin`. Логика панели, бота и агента не изменилась.

## Что изменилось

- Ссылки на репозиторий, установочный скрипт и проверку обновлений ведут на `mslab-tech/remnawave-admin`.
- Образы публикуются в `ghcr.io/mslab-tech`: `remnawave-admin`, `remnawave-admin-web-backend`, `remnawave-admin-web-frontend` и `remnawave-admin-node-agent`.
- Миграция `0128` обновляет адрес загрузки исходников во встроенном скрипте `update_agent`. Пользовательские скрипты не изменяются.
- Документация остаётся только на русском в Markdown и читается на GitHub. Отдельный сайт документации, график звёзд и Contributor License Agreement удалены; основная лицензия проекта не изменилась.

## Важно

- **Сначала опубликуйте новые образы.** До успешного завершения Docker workflow и открытия пакетов GHCR обновлять панель и ноды нельзя: новые адреса образов ещё не будут доступны.
- **Compose на существующих нодах нужно обновить вручную.** Миграция панели меняет сохранённый скрипт обновления, но не файл `/opt/remnawave-node-agent/docker-compose.yml` на нодах.
- Обновление агента пересоздаёт только его контейнер. Xray и клиентские подключения продолжают работать, но возможно короткое переподключение агента к панели.

## Обновление

### 1. Панель

Снимите [бэкап базы](../guide/backups.md) и сохраните текущий `docker-compose.yml`. В каталоге репозитория:

```bash
git pull
docker compose pull
docker compose up -d
docker compose exec web-backend alembic current
```

Последняя команда должна показать ревизию `0128`. Проверьте состояние контейнеров и откройте веб-панель:

```bash
docker compose ps
docker compose logs --tail 100 web-backend
```

### 2. Одна тестовая нода

Сохраните текущий compose, скачайте новый и пересоздайте только агента:

```bash
cd /opt/remnawave-node-agent
cp docker-compose.yml docker-compose.yml.before-5.2.1
curl -fsSL --retry 3 \
  https://raw.githubusercontent.com/mslab-tech/remnawave-admin/main/node-agent/docker-compose.yml \
  -o docker-compose.yml
docker compose pull
docker compose up -d
docker compose logs --tail 100 node-agent
```

Файл `.env` и токен агента не меняются. Если в compose были собственные настройки, перенесите их в новый файл перед `up -d`. После успешной проверки тестовой ноды обновите остальные ноды партиями.

Для новой установки используйте команду из обновлённой панели. Агент по-прежнему имеет внутреннюю версию `1.9.0`; `5.2.1` — версия релиза панели.

### 3. Проверка публикации образов

С машины без сохранённого логина GHCR:

```bash
docker logout ghcr.io
docker pull ghcr.io/mslab-tech/remnawave-admin:latest
docker pull ghcr.io/mslab-tech/remnawave-admin-web-backend:latest
docker pull ghcr.io/mslab-tech/remnawave-admin-web-frontend:latest
docker pull ghcr.io/mslab-tech/remnawave-admin-node-agent:latest
```

### Откат

До обновления сохраните прежние образы на серверах и резервные копии compose. Для отката панели сначала выполните `docker compose exec web-backend alembic downgrade 0127`, затем верните прежний compose и запустите сохранённые образы без `docker compose pull`. На ноде восстановите `docker-compose.yml.before-5.2.1` и выполните `docker compose up -d`, также используя локально сохранённый образ.

Миграция `0128` не меняет схему базы и не откатывает содержимое встроенного скрипта. Откат на прежнюю версию вернёт и прежние адреса установки агента, поэтому он возможен только как временная мера, пока прежние ресурсы и образы ещё доступны.
